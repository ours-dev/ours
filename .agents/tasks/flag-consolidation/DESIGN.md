# flag-consolidation: keep only the flags that something reads, each owned by one layer

**Date**: 2026-10-03
**Status**: Proposed

## Problem
The user, 2026-10-03: flags were added without much thought, some duplicate each other, and some are not used and never will be; decide which to keep. The memory-management and object layers carry about thirty flag and option enums, many copied from Linux's names (PG_*, GFP_*, SLAB_*, VM_*) for features this kernel does not have. Two consequences are visible today:
- A setter assigns the whole field, so every mark_*() erases the other flags (docs/repairs/261003/mm.md, item 1). It went unnoticed because nothing reads most of the bits it erases.
- One concept lives in several enums at several layers. Pinning, for example, is in page::Flags, VmmBody, VmoFlags, CommitOptions, VmMapOption, VmaFlags and PageQueues, and they do not agree on what it means.

## Goals and non-goals
Goals:
- Every flag that remains is read by something that changes behaviour, or is a hardware mirror.
- Each concept has one owner, named after Zircon where the concept is Zircon's.
- The set_flags() overwrite is fixed in the same pass, with the right acceptance test.

Non-goals:
- New features behind the flags: pinning, reclaim, NUMA policy, ASLR. Their TODOs move to docs/repairs.
- Renames for consistency alone, such as Gaf to something Zircon-like or VmaFlags Read/Write/Exec to CanMap*.
- Performance work. Two items (cache-line alignment of caches, upgrade-instead-of-remap on faults) are recorded for the user, not done.

## Design
How this was decided: a workflow of 17 agents over four groups (frames, VM objects, address spaces, paging and objects). In each group an auditor listed every flag with its writers and readers, an advocate argued to keep each and another to remove it, and a judge ruled with Zircon and Linux sources. A final agent reconciled the groups and re-checked the claims with git grep against HEAD 8bfa2a79. Spot checks of the most consequential claims (the setter overwrite, ALLOWED_GAF, the Active readers) agree with the code.

Totals: 124 entries; 75 remove, 28 keep, 13 fix, 5 merge, 3 rename.

### Naming

- **Flags vs Options.** After the cleanup, state words are `Flags` (VmoFlags, VmCowPages::Flags, VmaFlags, VmasFlags, page::Flags) and request words are `*Options` (VmMapOptions). Gaf stays as the Linux-derived term; renaming about 100 lines buys nothing.
- **Zircon names where the concept is Zircon's:** AlwaysPinned, Role::Free, LifeCycleState {NotReady, Alive, Dead}, CanMapSpecific, commit_range_pinned.
- **Our own names:** VdsoClaimed. Reserved keeps its name and is documented as Zircon's WIRED; unwire_frame keeps Zircon's verb.
- **None = 0:** add VmoFlags::None. VmMapOptions, VmaFlags, VmasFlags and VmCowPages::Flags already have it.
- **Underlying types:** VmMapOptions gets u32 (it is int today while its values are ULL), VmasKind gets u8.
- **Discache:** do not rename it to Uncached. Ours sets PCD only, which is UC-; Zircon's UNCACHED is strong UC, so the Zircon name would promise something we don't do. Document it as PCD-only instead.
- **New collision found:** bootmem::MemoryType::Mmu means "handed to mm", but page::Role::Mmu means "page-table page", and role_of() (memmap_init.cpp:83) maps MemoryType::PageTable to Role::Mmu. Rename MemoryType::Mmu to Managed, which matches Linux's managed pages and our m_managed_frames.
- **Considered and not recommended:** renaming VmaFlags Read/Write/Exec to CanMapRead etc. to match CanMapSpecific. It is churn with no behaviour change.

### Folding in the set_flags() overwrite fix (docs/repairs/261003/mm.md item 1)

**What the code shows:**
- Today the overwrite does real work by accident. mark_reserved() clears Initialized, so stamp_reserved_frames() skips holes and frames a second reservation shares, and no frame is counted twice.
- A plain OR would start counting holes and shared frames. The repair item's Change ("counts may grow") and its Acceptance ("page table has Reserved and Pinned") are both wrong.
- Only page-table frames lose Reserved today, because mark_pinned() overwrites it.

**How the setters should look (option A):**
- Delete `set_flags()` so no setter can assign the whole field.
- `init()` is the only whole-field write: `m_status.set<Index::Flags>(Flags::Initialized)`.
- `mark_reserved()`: `DEBUG_ASSERT(!(flags() & Flags::Reserved))`, then `m_status.set<Index::Flags>(flags() | Flags::Reserved)`. The assert makes counting a frame twice loud.
- `clear_reserved()`: `m_status.set<Index::Flags>(flags() & ~Flags::Reserved)`.
- stamp_reserved_frames() gets `if (frame->flags() & page::Flags::Reserved) continue;` before mark_reserved(). This states openly the de-duplication the overwrite was doing by accident.
- mark_pinned() and mark_active() are deleted.

**Acceptance:**
- The per-type `Reserved N frames (K KiB) of <type>` log lines are identical before and after, on both images.
- Page-table frames keep Reserved and Mmu, so the guard in free_frames_phys_range() can now see them.
- The debug image still boots. init()'s double-init assert and the new mark_reserved() assert are now live for reserved frames.
- Delete the repair item and add a change record in the same commit.

**Under option B instead:** Flags would be written only by init(), so set_flags() and every mark_*/clear_* go. The stamp skips frames that are already Wired or Mmu. The five readers switch to is_role(Wired), including vm_object_paged.cpp:135.

**Separate repair item, not fixed by either option:** one page::Status word holds Role and Order (written by the buddy under the zone lock) next to Role and Flags (written by the frame's owner with no lock, through become() and unwire_frame()). FrameBuddy::is_mergeable() reads a neighbour's word, which is formally a data race. Zircon uses relaxed atomic_ref and documents the racy queries (page.h).

## Alternatives considered
- Keep the Linux-shaped flags for the features they name. Rejected by every judge: a flag with no reader documents a feature that does not exist, and the setter bug shows that unread bits hide real breakage.
- Delete everything not read today, stubs included. Rejected in part: a stub that marks a Zircon concept we will build (VmmBody::pinned_count, the reclaim and compact entry points, the pager's supply_pages) stays.

### Disagreements between the judges, and how the consolidator settled them

- **Reserved, A vs B.** The frames judge recommends B (Role::Wired). The consolidator recommends A: keep the flag and fix the setters. Our reserved count follows Linux (present − managed), and a boot page table is both Mmu and on that count. Under B, a boot page table and a runtime one are both just Role::Mmu, so a future free can't tell which count to subtract from. Linux's free_pagetable makes exactly this distinction by testing PageReserved. Zircon can merge the two only because it keeps no reserved count. A also leaves vm_object_paged.cpp alone, which is not true of B, and it matches the "Reserved = WIRED, documented" conclusion of the last turn.
  - **Revised 2026-10-04.** A second check against the code and the Linux and Zircon sources refuted the three premises above. The managed count is a free count (`PmZone::finish_allocation()` subtracts, the free path adds), and nothing reads `reserved_frames`, so there is no Linux-style present-minus-managed identity to protect. Nothing frees a boot page table, and if something did, A's own asserts would refuse it. Zircon does count per page state; it keeps physboot's tables off WIRED by making them MMU at hand-off (`HandoffPageTablesFromPhysboot()`). The user then chose A for another reason, which holds: Role is a frame's use, and "held since boot" is an attribute of a frame whatever its use, the line Linux draws between `page_type` and `PG_reserved`.
- **Pin bookkeeping in VmmBody and pmm.hpp.** The frames judge would delete it all; the vm-objects judge would keep it under the hands-off rule. Resolution:
  - Keep VmmBody::pinned_count: it is where Zircon's pin_count goes.
  - Delete VmmBody::num_users: Zircon has no counterpart, and vm_aspace.cpp:36 already calls it a leftover.
  - Delete the undefined pin_frame()/unpin_frame() [U]: in Zircon, pinning is a VmCowPages operation, not a PMM one.
  - Keep PageQueues::set_pinned and QueueType::Pinned.
- **PermMask.** The paging judge wants a rename on the VmaFlags side; the aspaces judge wants it redefined. Redefine: once Share is gone, both layers mean the same set.
- **ZERO_PAGE.** This was open only under B. Under A it stays Role::Vmm and only its mark_pinned() call goes.
- **Runtime Role::Mmu vs the Reserved assert.** Under A, freeing a boot-built table through free_page_table() fails loudly in PmNode::free_frames, which is the right behaviour until something frees boot tables. Only PageTable::destroy frees tables today, and the kernel aspace is never destroyed. Record this as a repair item.
- **Ordering.** The vm-objects judge's "Lazy first" still holds. reserve() must stop passing Pinned before create() goes through commit_range_pinned(), or the 0-byte VMO gets InvArgs and boot fails. The MemCache::Option value→Gaf mapping must go before the Gaf bits it writes.
