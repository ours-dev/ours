# ipi —— 待修项（2026-09-10）

## 1. `IpiEvent::Interrupt` 两头都是空的

**严重程度**：低。没有发送方，`x86_handle_ipi_interrupt()` 也是空函数体。

和 `IpiEvent::Suspend` 不同——Suspend 的处理器写明了它要做什么
（停住这颗 CPU），只是缺一个发送方，所以 2026-09-10 把发送方补上就成立了。
Interrupt 是**两头都空**，树里没有任何东西说明它本来打算表示什么。

Zircon 的 `MP_IPI_INTERRUPT` 是"目标自己去处理一个挂起的中断"，配合
`mp_interrupt()` 用于把设备中断转投到别的 CPU 上。ours 还没有中断转投。

按本仓库的惯例，空的声明默认当脚手架、不删。它缺的是一个**用途**，
不是一个实现——等真的有东西需要"把中断交给另一颗 CPU 处理"再来填。

## 2. `sync_exec()` 只有同步版

`IpiService::sync_exec()` 在所有目标跑完之前不返回，请求放在调用者栈上。
这对"在每颗 CPU 上开关计数器并等确认"这类用途正合适，也是它能不分配、
能在早期引导可用的原因。

缺的是 Linux `smp_call_function_single_async()` 那种"发了就走"。它需要另一套
所有权模型（请求不能放在调用者栈上），等有客户再说。
